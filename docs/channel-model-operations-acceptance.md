## 独立代码审查修正

- 网关只路由 `HEALTHY/DEGRADED` 渠道模型；损坏的遗留成本规则只隔离当前候选，不影响其他可用候选。
- 发布检查要求同一个候选同时满足渠道健康、模型健康、Key 可用和当前采购成本可解析，避免跨候选拼接健康与成本。
- 推理 Token 从普通输出 Token 中扣除后再按独立单价计算，避免双重计费。
- 成本规则增加 DTO、领域函数和 PostgreSQL CHECK 三层校验；渠道成本时区校验 IANA 标识。
- 模型探测使用乐观并发更新并在定时扫描时原子认领；普通 4xx 走连续失败，仅 401/403 和明确的 `model_not_found` 直接下线。
- 测试台真实消费上游流并逐条转发 `delta`，记录首字延迟；客户端中断会取消读取且不更新健康状态。
- 相同渠道模型的成本规则写入使用 PostgreSQL 事务级 advisory lock 串行化；真实数据库并发烟测结果为一项成功、一项 `ConflictException`，最终只持久化一条规则，测试数据已清理。
- 渠道 24 小时 P95 改为 PostgreSQL 聚合；统计入口使用强类型 DTO，历史成本规则优先按不可变快照 ID、名称和时段归因。

## 性能说明

当前开发库数据量较小，PostgreSQL 会选择顺序扫描，不能据此声称已达到百万用量日志下的 P95 指标。发布到大数据量环境前，应使用脱敏性能数据执行 `EXPLAIN (ANALYZE, BUFFERS)` 和 P95 压测；所需复合索引已随迁移创建。本次未向共享开发库灌入 100 万条模拟用量，避免污染现有业务数据。

# 0.7.0 — 组负责人门户、员工登录与预算申请登记

状态：2026-09-18 发布准备完成，尚未部署公司服务器。功能提交区间 `ec33e5e..90fe299`（基于 0.6.0 后主线 `11e039f`），本地合并回 `main` 后执行发布准备；本文件所在提交即本次发布源提交。

## 变更范围

- 管理员创建用户时可设置初始密码，并可对已有账号设置/重置密码（`POST /api/v1/admin/users/:id/reset-password`）；重置递增 `tokenVersion` 使旧网页会话立即失效，审计不记录密码明文。无密码账号仍可仅凭员工 Key 使用模型，个人中心登录不再是 Key 使用的前提。
- `GroupMember` 新增组内角色（`LEADER`/`MEMBER`，存量默认 `MEMBER`）；管理员在组详情设置/取消负责人，一人可负责多个组，移出组即失去负责人身份。
- 新增负责人只读门户 `api/v1/me/led-groups`：所负责组的预算概览与告警、单组预算摘要、组内用量（按成员/按模型聚合 + 明细分页），全部服务端校验负责组范围，拒绝设备会话；个人中心新增「我负责的组」页签。
- 新增预算申请登记 `group_budget_applications`：负责人在线提交（或管理员代登记），管理员可驳回，或在执行额度调整时关联待批复申请——同一事务置 `LINKED` 并回填批复金额、批复人、时间与关联调整流水，形成"申请→批复→调整"台账；已决定申请不可重复批复，不带申请的调整流程不变。
- 管理端组详情预算页新增申请记录区（登记、状态、批复金额、关联流水、驳回）与额度调整的申请关联选择；用户详情新增密码状态与设置/重置入口。

## 升级兼容性

相对 0.6.0 **新增 1 条数据库迁移**（`20260918072655_group_leader_budget_applications`，迁移总数 16 → 17）：`group_members.role` 列（`NOT NULL DEFAULT 'MEMBER'`，存量数据自动落 `MEMBER`）、`group_budget_applications` 表及 `budget_application_shape` CHECK 约束，另含 Prisma 检测的 `channel_abilities`→`channel_models` 历史约束/索引命名漂移修正（对既有数据无影响）。迁移由 `./install.sh update` 自动执行，升级前照常创建数据库备份；**`MASTER_KEY` 必须保持不变**。

无新增依赖、无网关协议变更；员工 Key、设备授权、渠道密钥与既有预算结算行为不变。既有无密码账号升级后保持无密码，直至管理员显式设置。

版本号已同步到 `package.json`、`package-lock.json`、`conf/.env.example` 和 `DEPLOY.md` 镜像加载示例；未修改实际 `.env` 或生产配置。

## 发布操作流程

1. 构建离线升级包后核对包哈希与目标当前版本（应为 0.6.0）；如源代码或配置范围变化，重新明确发布来源。
2. 依照 [部署说明](../DEPLOY.md) 核对健康、空间、外部网络和 Compose，创建新鲜数据库备份，保留 0.6.0 镜像与发布文件。
3. 升级配置仅调整 `VERSION=0.6.0` 至 `VERSION=0.7.0`；保留其他配置字节及 `MASTER_KEY`。通过 `./install.sh update` 升级，确认执行且仅执行 1 条新迁移（迁移总数 17）。
4. 验证四个应用容器镜像、API/Gateway 健康及外部页面；登录后验收：为测试账号设置密码并可登录个人中心、指定组长后可见「我负责的组」、提交一笔预算申请并由管理员关联批复，台账可查；随后补充实际部署日期与记录。

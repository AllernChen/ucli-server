# 渠道、模型与采购成本管理验收记录

验收日期：2026-08-23
验收环境：本地 PostgreSQL、Redis、API `:3000`、Gateway `:3001`、Admin `:5174`、Worker

## 验收范围

- 渠道、Key、渠道模型、分时采购成本、公共模型和兜底采购成本的创建、查询、编辑、启停、归档及恢复。
- 按上游模型 ID 绑定现有公共模型，或在绑定时创建公共模型。
- 公共模型按厂家聚合；渠道模型与公共模型页面展示同一份实际采购成本。
- 固定渠道模型的对话测试，以及按组织、渠道、模型、员工和成本规则进行内部用量与采购成本分析。
- 平台金额统一使用人民币采购成本，不包含员工销售价格、收入或利润计算。

## 生命周期与安全语义

- 删除采用可恢复归档；历史用量、路由尝试和采购成本快照保持关联。
- 归档配置不会参与员工目录、网关路由、模型测试、自动探测或采购成本解析。
- 渠道、Key、渠道模型、成本规则和兜底价格恢复后保持停用，需要管理员显式启用。
- 活动分时成本和兜底价格仅允许 CNY；归档旧币种历史保持不可变，不能直接恢复为活动配置。
- 自定义模型发现地址必须与渠道基础地址同源，防止向其他站点发送渠道 Key；401/403 会按渠道策略隔离无效 Key。

## 本地验收结果

- DeepSeek V4 Flash：渠道分时采购成本输入 `¥1/M`、输出 `¥2/M`；公共模型兜底为 `1/2/0.02/2 CNY`。
- DeepSeek V4 Pro：当前使用公共模型兜底 `3/6/0.025/6 CNY`。
- 模型目录按 DeepSeek 聚合显示两个模型；渠道详情可直接维护绑定、测试和成本规则。
- 模型对话测试页可选择渠道、渠道模型、Key、流式参数和多轮消息。
- 统计分析页展示请求、Token、采购成本、员工、延迟和多维明细，金额使用 `¥`。
- API、Gateway 和 Admin 健康检查均返回 HTTP 200，PostgreSQL 与 Redis 依赖正常。

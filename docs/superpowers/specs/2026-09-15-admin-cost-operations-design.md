# 管理端用量与成本运营页面升级设计

日期：2026-09-15。基线：0.4.1，代码 `9c04cd5`。状态：用户已确认本文，进入实施计划阶段；尚未实施。

## 1. 目标与边界

在现有使用日志、统计分析、用量组、服务总览上补全管理能力，实现“总览发现问题 → 分析定位 → 用量组管理 → 请求明细核对”。公司统一采购，员工使用，所有金额均为人民币采购成本，不计算销售价格。

采用现有 Vue 页面、ECharts 图表、API、usage_logs、route_attempts、组预算记录；不新增账本、报表平台、采集服务或依赖。已有实现可以复用则直接复用，仅提取被这些页面实际共用的查询与展示逻辑。相比另建报表系统，扩展现有接口能保留权限和历史记录，代价是必须补足现有查询口径和兼容测试。

本次不改变网关预算预估、扣减、缓存适配或结算机制，不改历史数据、价格配置、组额度、员工 Key 和生产环境。不增加主机 CPU／内存／容器监控，不新增人工调账操作。开发完成后先本地验收，发布另行确认。

## 2. 已确认的现状

- `apps/admin/src/Dashboard.vue` 仍按数组读取现已返回分页对象的渠道列表；把 timeoutMs 当延迟展示；汇总没有日期范围。
- `Analytics.vue` 已有时间筛选、趋势和多维分析，但维度列表固定取前 50 条，无分页、导出、缓存细分和使用日志跳转。
- `UsageGroups.vue` 已有分页、生命周期及预算进度，但每组另请求一次预算；一条预算加载失败可能影响整页。
- `UsageGroupDetail.vue` 已有成员、模型权限、预算调整与流水、嵌入使用日志，继续保留这些流程。
- `Usage.vue` 已有归属和路由记录，但缺少可读的费用分解、预算关联和对账导出。
- analytics 与 usage summary 把 UNKNOWN 费用记录排除在请求成功数之外；渠道统计有路由成本依据，但用量不能重复使用整条请求的总 token。
- 现有 `/healthz` 和 `/gateway/healthz` 可用于入口与 PostgreSQL／Redis 的健康检查；一次检查失败不能据此断言具体哪个依赖故障。

## 3. 全页面指标契约

### 3.1 金额、用量、状态

1. 金额使用服务端 Decimal 和现有 8 位精度。API 提供 `costCny` 字符串，保留已有 `costUsd` 兼容别名，前端不做汇率转换。明细保留 8 位，汇总可简写但能查看精确值。
2. 输入总量包含缓存命中量：未命中输入 = max(输入总量 − 缓存命中量, 0)。输出总量包含推理量，输出细分不重复加算。缓存命中率按 token 加权计算，不平均各请求百分比。
3. 优先使用厂商返回并已归一化的用量；ESTIMATED 明确标记为估算。缓存率仅使用有可信缓存统计的调用，展示统计覆盖范围；缺失字段显示“未提供”，不声称实际零命中，不反推厂商缓存。历史记录若只保留归一化默认零而无来源证据，则不能区分未提供和零命中，标记覆盖未知，不补写历史数据。
4. 请求状态与计费状态独立筛选和显示。请求结果分类顺序：客户端取消、流中断、失败、成功；失败包含 HTTP 非成功值或已记录 errorCode。成功须为 2xx 且没有错误、取消、中断。无请求显示“—”，不显示 100%。
5. 计费状态沿用 CONFIRMED、ESTIMATED、UNKNOWN、NO_CHARGE。展示已记录成本、其中估算成本、待核算请求数；UNKNOWN 的已知部分仍计入已记录成本，未知部分不是零费用。接口使用明确的新请求成功率字段，旧 successRate 保留兼容并注明旧口径；本次四个页面全部迁移到新口径。
6. 明细价格来自请求／路由历史快照，显示规则名称、有效时段、时区和每百万 token 单价。不拿当前价格重算历史；快照缺失显示“历史价格信息不足”。公式展示复用现有采购成本计算函数，记录成本仍为权威值；人工核算或舍入差异需明确说明。
7. 多渠道调用按 route_attempts 分别归属成本与用量；同一请求在同一渠道的多次尝试先合并。渠道请求数按该渠道涉及的 request 去重，各渠道请求数不可相加当平台总请求数。只有旧记录没有可用路由计费信息时，才以最终渠道归属并标明历史口径。
8. 渠道已知成本必须可加总对齐请求已知成本。若人工核算后请求总额与路由合计不一致，差额单列“未分配到渠道的核算差额”，不擅自分摊；缺路由用量不复制全请求用量，显示覆盖不足。
9. 价格分析按历史规则及实际价格快照区分，包含命中时段；同一规则修改前后的价格不可混成一个“当时单价”。仅有请求级价格的旧记录单独标记，不假造路由价格。

### 3.2 时间与筛选

- 管理端统计默认以 Asia/Shanghai 展示与切分自然日，页面明确标注时区；使用半开区间 `[start, end)`，UI 的结束日期包含整天。URL 保存明确的起止时间与筛选条件，后端以 UTC 时刻查询，在所选统计时区分桶。
- 现有 API 未传时区继续保持 UTC 行为；新页面明确传 Asia/Shanghai。日期控件不依赖浏览器本地时区解析。统计默认近 7 天，保留 7／30／90 天与自定义范围，最多 90 天。
- 共用组织、员工、组、员工 API Key、凭据类型、渠道、公共模型、渠道模型、价格规则／快照、请求结果、计费状态筛选；使用日志另支持 requestId。明确“全部”和历史未归组／无 Key 的区别。
- 筛选应用后才更新 URL 和结果标题；快速切换时旧请求不能覆盖新结果。分析跳日志、日志返回、组内跳分析均保留已应用条件。组内嵌入日志始终固定当前 groupId，URL 不能覆盖。
- 请求状态筛选针对完整请求；渠道／价格筛选下的计费状态针对匹配路由。详情同时展示请求总额和匹配部分；导出和汇总使用同一匹配范围。

### 3.3 预算与权限

- 当前预算周期依组的 TOTAL／MONTHLY 和 budgetTimezone 计算，与图表日期范围分开显示。不汇总不同周期组的额度为“公司月预算”。
- 有限预算可用 = 额度 − 已用 − 当前预占；待核算预占是当前预占的子集，不能再减一次。无限额与额度为零分别展示；超额保留负可用金额，不伪装为零。
- 流水 SETTLED／RELEASED 中保留的 reservedCny 是历史预占，不是当前占用。详情分别显示初始预估、追加预占、累计预占、当前保留、已结算及状态。
- 保持现有角色范围：平台管理员可跨组织查看使用分析；组织管理员只看本组织；员工只看自己。用量组及预算管理仍限当前组织的管理员，服务总览仍限平台管理员。
- 总览成本卡片默认平台范围，预算提醒明确标注“当前组织”，不能暗示覆盖所有组织。不可访问的管理链接不显示。
- 请求详情先鉴权查询 usage log，再按组织、员工、组、请求及凭据身份关联预算。员工只能看本人请求的安全费用投影，不得到组剩余额度或其他员工记录。权限不匹配的关联不返回。
- 新详情和 CSV 使用字段白名单，不返回渠道密钥、员工 Key 明文、Redis 预占标识或整个内部 budget snapshot。

## 4. 页面设计

### 4.1 使用日志：可核对的请求明细

保留主表，补齐 requestId、员工／组／Key 名称、渠道／模型、未命中输入／缓存命中／输出、人民币成本、请求状态和计费状态。名称优先使用历史 actorSnapshot，无法恢复时显示 ID，不把改名后的名称冒充历史名称。

每行通过详情抽屉显示：基本归属 → 各次渠道调用 → 历史价格与费用分解 → 本请求预算预占／结算。默认可读字段，不以原始 JSON 代替说明。无组的旧请求显示“不适用组预算”；缺记录显示“未找到关联记录”。请求可能涉及多次尝试，展示顺序遵循 attempt。

筛选使用可搜索的名称选项，保留 ID 定位和 requestId 精确检索。支持分页、刷新、清空、复制 requestId 和按当前筛选导出；空数据、权限不足和加载失败分别处理。

### 4.2 统计分析：维度与成本定位

上方筛选栏，下方概览卡、趋势图、维度明细表。保留现有维度，补未命中输入、缓存命中、命中率及覆盖、请求成功率、估算成本和待核算数量。失败分类先使用已有错误码／取消／中断记录，不创建错误采集服务。

维度表有服务端分页、稳定排序、总行数及 CSV；价格维度显示输入／缓存／输出／推理单价及历史时段。点击行可继续维度筛选或查看匹配使用日志，不能仅在分析内部跳转。

渠道维度展示涉及请求数、路由用量与路由成本，说明非可加总的请求数；无路由资料与未分配差额使用明确的历史／差额行。每个汇总金额均能定位来源，不用最后一次调用价格推导整个请求成本。

### 4.3 用量组：额度和配置是否可用

列表保留搜索、类型、启停／归档与分页。补有效成员数、授权模型数、有效员工 Key 数、当前周期、已用／预占／待核算／可用金额及占用比例。有效成员遵循现有组访问检查的账号、组织成员及组成员状态；有效 Key 指未撤销、未停用、未过期，不等同于保证可调用。授权模型数是配置数量，不冒充实时健康可用数量。

在现有列表响应中批量附加预算摘要，不由浏览器逐组请求，也不在服务端简单循环原单组方法。摘要采用受组织限制的批量查询，缺当前周期时按原 summary 默认额度规则展示，不创建预算周期记录。

有限预算占用 `(已用 + 预占) / 额度 >= 80%` 提醒，达到／超过额度标“额度不足”；零额度直接标不可用，无限额不显示百分比。阈值固定用于本次展示，不增加设置模块。另提示未绑定有效成员、未授权模型、待核算；没有员工 Key 只作为配置提示，因为设备授权也能使用。

详情保留成员、模型和有审计的预算操作，补近 7／30／90 天组成本趋势、员工／模型／Key 排行及分析入口。预算区始终说明当前预算周期。预算流水用中文状态和明确金额标签，并提供关联 requestId 的明细跳转；额度调整记录没有请求时不显示请求链接。

### 4.4 服务总览：快速发现问题

展示今日／本月成本和所选期间请求数、成功率、活跃员工、token、缓存命中；默认今日，可切本月，并展示近 7 天成本与请求趋势。

渠道区正确读取分页对象，展示渠道配置状态、已有健康状态和有明确时间窗口的实测延迟。timeoutMs 只称“超时设置”，没有实测数据则显示“—”。不在打开总览时触发上游付费模型测试。

健康区读取 API／Gateway 现有健康检查，展示检查时间、可达／检查失败／未取得结果。不能把一次失败包装成某个具体依赖宕机。补本地开发 Gateway 代理以使用相同路径；不修改生产部署配置。

提醒区：启用但异常的渠道、当前组织预算不足或达到 80% 的组、待核算请求。提醒为当前状态，不受历史趋势日期误导；每区最多展示前 5 项，并给出正确总数和“查看全部”入口。不能把第一页数量当全部总数。摘要通过有界、受权限限制的数据库查询获得，不拉全库到浏览器。

健康、成本、渠道和预算区独立显示加载／错误／重试；显示最后成功更新时间。手动刷新，不新增后台轮询任务。

## 5. 实现接口与复用边界

- 扩展 `analytics.dto.ts`、`packages/usage/src/analytics-types.ts` 的可选筛选和新增结果字段，使用白名单校验、参数化查询及确定性排序。旧 `/usage/logs` 保持数组返回；分页 metadata 通过新增 `/usage/logs-page` 提供，避免破坏原客户端。
- `AnalyticsService` 内统一 overview／timeseries／breakdown 的查询口径；`UsageController` 在相同权限和筛选约束下提供分页、请求详情 `/usage/logs/:id`、CSV `/usage/export`。固定路径先于动态路径声明；旧 summary 字段保留，新增明确口径字段。
- 统计维度导出使用 `/analytics/export`，与 breakdown 复用筛选、排序、分组和金额投影；总览聚合需求放在现有监控模块的受限 overview 接口，不另建监控模块。
- 仅在既有查询中提取实际共用的规范化和权限约束；不创建通用报表 DSL、插件系统或一实现接口。现有 TrendChart、抽屉、分页、人民币格式化优先复用。
- 两类 CSV 都按已应用筛选导出，不限当前页，最多 5000 行。服务端最多取 5001 行，超限返回明确错误并提示缩小范围，不静默截断。使用 UTF-8 BOM、正确转义逗号／引号／换行，并防止名称等用户可控单元格触发 Excel 公式。导出白名单不含原始请求体／响应体或内部快照。
- 页面级筛选选项保留当前选中值和历史 ID；修改某一维度时可查询该维度的其他可选项，避免被当前值锁死。查询必须与数据相同地限制员工／组织可见范围。
- 不预先增加缓存或物化汇总。首次以已有索引和限制时间范围的 SQL 聚合实现；若本地代表性数据的查询计划证明确有瓶颈，再提出必要索引，不能为假定吞吐新增系统。

## 6. 验收标准

1. 相同权限、日期和筛选下，总览／分析／日志导出已记录成本一致；组预算独立显示其当前周期，不拿部分日期日志声称等于全部已用。
2. 测试缓存命中、估算用量、缺缓存统计、分时价格边界、规则改价、同请求跨渠道和同渠道多次重试；分项不重复，历史价格不漂移。
3. 测试成功但 UNKNOWN、失败但有成本、取消、中断、NO_CHARGE、人工核算差额；状态筛选和已知费用一致，缺失不冒充零。
4. 测试 RESERVED、SETTLED、RELEASED、RECONCILIATION_REQUIRED；已结算记录历史 reserved 不算当前预占，uncertain 不重复扣减；无限额／零额度／超额／跨月及 TOTAL 组标签正确。
5. 真实数据库集成测试覆盖平台／组织／员工权限、伪造跨组织筛选、跨员工请求详情、预算关联和导出；禁止泄露密钥与内部预占标识。
6. 测试 CSV 5000／5001 行、中文及危险单元格、同时间稳定排序、分页和导出筛选一致性；历史名称、未归组、无 Key 均可定位。
7. Vue 测试及本地浏览器验收覆盖四页面导航链、返回保留筛选、嵌入组固定、空态、独立模块失败、过期响应、刷新和基础键盘操作。
8. 总览渠道列表适配与延迟回归测试；组列表不发 N+1 预算请求；健康失败不显示虚假正常或具体依赖结论。
9. 使用现有测试框架扩展相关用量、分析、组预算和管理端测试，执行针对性测试后再运行 `npm run verify`。测试数据和本地模拟不调用生产付费模型、不改生产记录。

## 7. 交付顺序

1. 共享筛选／权限／指标口径与请求费用、预算安全投影，补核心回归用例。
2. 使用日志详情／导出及统计分析维度／分页／跨页联动。
3. 用量组批量摘要、配置提示、组内趋势与流水关联。
4. 服务总览与异常入口，本地完整回归和浏览器验收。

# 用量组、员工 API Key 与人民币预算升级方案

状态：用户已确认继续，进入实施规划；包含随后确认的 AI CLI 模型发现和协议接入要求。尚未实施或部署。

## 1. 已确认的范围

- 平台面向公司内部，按人民币采购成本管理，不计算员工销售价格。
- 部门小组和项目组统一称为“用量组”，通过类型区分。
- 员工可以加入多个组，一个组可以有多名员工。
- 平台签发员工 API Key；每个 Key 固定属于一个员工和一个组。
- 员工可直接使用服务端地址和 Key，通过外部工具或脚本调用模型。
- UCLI 设备 Token 与员工 API Key 并存，复用模型网关和成本计算。
- 公司采购的渠道密钥始终由服务端保管。
- 服务端作为公司统一 AI API 网关，支持兼容 AI CLI 通过员工 Key 接入，并提供按权限过滤的模型发现能力。

## 2. 方案比较与推荐

| 方案 | 优点 | 代价 | 结论 |
| --- | --- | --- | --- |
| 在现有组织、员工、网关内增加用量组和员工 API Key | 复用采购配置、路由、设备授权、用量统计 | 要补齐组权限和预算结算 | 推荐 |
| 把每个组建成一个独立组织 | 可利用组织隔离 | 员工跨组管理、公司汇总和资源共享变复杂 | 不适合当前需求 |
| 单独搭建 API Key 与计费服务 | 可独立演进 | 多一套服务与一致性问题，当前规模无必要 | 暂不采用 |

一期使用现有 PostgreSQL、Redis 和应用部署，不新增服务或依赖。

## 3. 当前代码依据

- `prisma/schema.prisma` 已有 Organization、Account、Membership、Device、DeviceGrant；没有用量组或员工 API Key。
- `packages/security/src/auth.ts` 验证 JWT 和员工/组织/设备状态；API 与网关共用认证逻辑，需要保证员工 API Key 仅用于模型调用。
- `apps/gateway/src/gateway.controller.ts` 在模型目录及各模型调用接口强制要求 deviceId。
- `packages/gateway-core/src/access-policy.ts` 当前无策略时放行、有策略时任一匹配放行。组限制不能简单插入现有 OR 策略，否则可能被其他允许规则绕过。
- `apps/gateway/src/gateway.service.ts` 已支持路由、价格快照、分时成本、预占及结算，可在共享路径接入。
- UsageLog.deviceId 当前必填；projectId 来自客户端上下文，不能作为可信的组预算归属。
- `packages/quota/src/redis-quota.ts` 当前使用 Redis 计数与 UTC 周期，预占没有持久请求账目。组预算需要持久化和幂等结算。
- 既有成本字段部分仍命名为 costUsd，实际成本路径采用 CNY。新增领域明确使用 CNY，旧字段通过兼容映射读取，不对历史数字擅自换汇。

## 4. 分组和凭据规则

### 用量组

每组属于一个组织，包含名称、类型（部门/项目）、说明、状态、成员、允许模型及预算配置。不建立组织树或部门与项目的预算分摊关系；员工使用哪个组的 Key，就由哪个组承担一次成本。

管理员可创建、编辑、停用、启用、归档组及管理成员。已有成本或凭据关联的组删除时采用归档，保留历史。新组默认没有允许模型、预算为零，完成配置后才能调用。

### 员工 API Key

字段包括名称、所属员工、所属组、密钥摘要、显示前缀/尾号、状态、到期时间、创建人、创建时间和最后使用时间。

- 一个员工可有多个 Key，支持按工具或用途命名。
- 完整密钥仅创建时展示，使用高熵随机值；持久化不可逆摘要，日志与审计仅记录 Key ID/尾号。
- 支持修改名称、到期时间、停用/启用、撤销，以及创建替代 Key 进行轮换。
- 已签发 Key 的员工和组归属不可更改；切换组需创建新 Key。
- 撤销不可恢复；“删除”撤销凭据并隐藏列表项，保留引用。
- 一期由管理员为员工签发，员工可在个人页查看自己 Key 的状态、归属及用量并撤销自己的 Key。自助创建可后续增加。
- 移出组时永久撤销该员工在组内的 Key，并撤销相关设备组授权，重新加组不会自动复活旧凭据。
- 员工、组织或组停用后，下一次请求立即拒绝；已开始的请求继续记录并结算。
- 员工 API Key 只具有模型调用权限，即使持有人是管理员，也不能以此调用管理 API。

### UCLI 设备

设备授权增加固定组归属。签发授权时由管理员选择员工所在组，兑换设备时继承；网关从服务端授权记录读取归属，不信任客户端传入 groupId 或 projectId。

设备改组通过撤销旧授权并重新签发完成，历史调用归属不变。两种凭据在网关内都形成“组织、员工、组、凭据类型和凭据 ID”的可信身份。

## 5. 模型权限

实际允许调用的模型 = 平台启用模型 ∩ 现有组织/员工/角色策略允许模型 ∩ 当前凭据所属组允许模型。

- 一期在组内选择平台公共模型，不让员工配置或选择上游密钥。
- 组采用明确的模型允许清单，空清单代表无权限；新增平台模型不会自动授予已有组。
- 员工加入多个组不会合并各组权限。例如 A 组 Key 不能使用仅 B 组授权的模型。
- `/models` 与所有调用接口必须使用同一权限判断；直接填写未授权模型 ID 也会拒绝。
- 管理员在组详情中可预览成员的实际可用模型；现有策略阻止的模型显示原因。
- 一期不新增每个 Key 的模型白名单或额度，已有员工配额继续作为额外限制；有真实需求时再增加更细配置。

## 6. 组预算与费用结算

### 产品规则

建议一期支持两种互斥预算模式：项目总额（长期累计，不自动重置），自然月额度（每月独立，默认不结转）。创建项目组默认推荐总额，部门组默认推荐月额度，由管理员选择。

- 金额单位为 CNY；展示到分，计算和持久化保留八位小数，避免小额请求舍入成零。
- 0 表示不能使用；不限额必须显式选择，不能把空值或零隐含解释为不限额。
- 展示分配额度、已结算成本、处理中预占、待核对金额、可用额度。
- 可用额度 = 分配额度 − 已结算成本 − 未结算预占。待核对金额属于未结算预占，不重复扣减。
- 管理员可追加或调整当前额度，记录前后金额、原因、操作人；额度不得降低至已结算加未结算预占之下。
- 月周期采用组的预算时区，新建组建议 Asia/Shanghai；上线前确认公司现有时区，不直接改变历史组织配置。
- 月请求按开始时间所属周期结算，跨月完成仍计入原周期；预算模式或时区调整在当前有请求的周期内禁止，需新周期或新组承接。
- 总额组重新分配总额度不清除已用成本；月额度调整明确区分当前周期额度与后续每月默认额度。
- 接近 80%、达到 100% 时在管理页提示，复用已有告警入口并按组/周期/阈值去重。

### 请求流程

1. 验证凭据、组织、员工、组和成员状态，并检查模型权限。
2. 解析允许路由与适用价格快照，校验输入及输出上限，估算本次最大预占成本。
3. 先通过既有速率、并发、员工/组织配额检查，再在 PostgreSQL 事务内原子检查并预占组金额。组预占失败时释放已取得的配额预占。
4. 转发上游请求，普通响应和流式响应使用同一结算入口。
5. 按实际渠道、请求开始时适用价格快照及实际 token 结算，多退少补，落用量日志。
6. 释放确认未发生消耗的预占；对可能已产生上游费用但结果不明的请求保留待核对状态。

预算是“请求前预占、实际成本结算”的控制。不能承诺上游异常或估算误差下实际费用绝不越额：若实际成本超出预占，必须如实记账、标记超额，并阻止后续请求。

预占采用当前候选路由中保守成本，并考虑上游协议、输入类型及输出上限。文本的字节数估算不能直接当作图像等输入的成本上界；不具备可靠估算能力的输入类型，在有限预算组中应拒绝并说明原因。预算控制必须确保输出上限实际传给上游；缺省值采用服务端上限。

### 持久性和异常

- PostgreSQL 保存预算周期、汇总与逐请求预占/结算记录，作为组预算依据；Redis 继续服务既有速率和 token 配额。
- 使用服务端生成的 requestId 作为内部结算幂等键，不能因流结束/断开双回调、重试结算而重复扣费；客户端重复发起的新请求是独立调用。
- 预占记录状态为 RESERVED、SETTLED、RELEASED、RECONCILIATION_REQUIRED。组额度检查与预占同一事务完成，使用行锁或条件更新防止并发透支。
- 用量日志和组结算同一数据库事务提交；持久预占记录需保存恢复所需的归属、周期和估价信息。提交失败保留预占、告警并重试，不能只打印错误后放行下一次预算。
- 服务重启后可找回未完成记录。超时记录不能自动假定免费；先区分尚未发送、已发送和结果不明，必要时由管理员依据记录做可审计调整。
- 客户端中途断开不代表免费：尝试终止上游，按已获得的 usage 或明确标记的估算记录消耗。对尚无法确定的剩余金额保留待核对状态。
- 上游重试/切换若产生多次可计费消耗，分别记录路由消耗并合计组成本；不能只核算最终成功尝试。有计费可能的模糊失败先保留对应预占，不盲目无限重试。
- 上游没有 usage 时将结果标记为估算；后续校正以调整记录体现，保留原值和操作依据。
- 数据库或必要配额依赖不可用时拒绝新调用，不跳过金额控制。
- 员工、Key、组等统计维度属于同一消费的不同汇总视角，不能相加产生重复公司成本。

| 页面 | 主要内容 |
| --- | --- |
| 用量组列表 | 类型、状态、成员数、预算模式、额度、已用、预占、可用、进度及搜索筛选 |
| 用量组详情 | 概览、成员、允许模型、预算与调整记录、使用明细 |
| 用户详情 | 所属组、员工 API Key、设备授权、按组汇总的个人用量 |
| 员工个人页 | 自己的 Key 状态/撤销、所属组、接入地址、示例、个人用量 |
| 使用日志 | 员工姓名、组、凭据类型、Key 名称/尾号或设备、渠道、模型、人民币成本及是否估算 |
| 统计分析 | 组、员工、Key、模型、渠道交叉筛选；成本趋势、预算消耗、token、请求量、失败率 |

管理操作沿用现有平台/组织管理员权限且严格限定组织；员工只能看自己凭据与个人明细。一期不新增组管理员角色。个人页复用现有网页登录身份，不允许员工 API Key 兑换网页登录会话。现有新员工默认没有密码：这类员工依然可直接使用管理员签发的 Key，个人页不构成调用前置条件，查询与撤销由管理员代办；一期不额外引入密码注册或找回系统。

员工接入的 OpenAI 兼容 Base URL 为现有服务地址加 `/gateway/v1`，API Key 填平台签发值；支持已有 models、chat/completions、responses 路径。模型和协议兼容性仍以平台实际配置为准。

OpenAI 兼容路径接受 `Authorization: Bearer <员工APIKey>`；既有 Anthropic messages 路径同时支持其客户端使用的 `x-api-key`。不同认证头冲突时拒绝，API Key 不支持 URL 查询参数传递。

外部工具仅凭地址和 Key 即可调用，无需伪造设备信息。常见失败使用兼容错误结构和稳定 code：凭据失效 401，组/成员或模型无权限 403，预算不足及速率限制 429，并返回请求 ID。新组预算错误不得伪装成上游无可用渠道。

### 模型发现和 AI CLI 接入

| 对外入口 | 返回或调用能力 |
| --- | --- |
| GET /gateway/v1/models | OpenAI 风格目录，保留 id、object、owned_by、display_name、context_size、protocols |
| GET /gateway/anthropic/v1/models | 新增同基址目录，只返回当前凭据有权使用且支持 anthropic_messages 的模型；data 中包含 id、display_name |
| POST /gateway/v1/chat/completions | OpenAI Chat Completions |
| POST /gateway/v1/responses | OpenAI Responses |
| POST /gateway/anthropic/v1/messages | Anthropic Messages |

两个目录都接受员工 API Key 或有效设备 Token，同一员工的不同组 Key 可以得到不同列表。目录查询不调用付费上游、不预占组金额，预算耗尽不隐藏已授权模型；实际调用明确返回预算不足。目录必须 Cache-Control: no-store，不允许共享缓存把一个组的清单返回给另一个组。

目录按当前有效配置和权限返回，protocols 不表示实时健康。短暂上游故障不能改变静态协议声明。健康检查复用既有渠道模型探测和管理测试台；不在每次 /model 时发起真实模型对话。

Anthropic 目录直接响应客户端的 `?limit=1000` 请求，不通过重定向跳往 OpenAI 目录。返回完整的已过滤目录，limit 是客户端兼容参数，一期不实现分页游标；超过适配规模再扩展分页。正常测试环境 1000 个模型应在客户端 3 秒超时内返回。

Claude Code 的可用版本可通过 `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1` 在启动时从 ANTHROPIC_BASE_URL 下读取 /v1/models。其客户端对模型 ID 有筛选，不能承诺 DeepSeek 等非 Claude 模型自动进入 /model，也不伪造 claude 前缀绕过筛选。列出不等于已验证完整工具能力；需测试真实使用的 CLI 版本。OpenCode 自定义 provider 使用其模型配置和 /models，提供对应配置示例。

现有三种公开协议不任意互转：Responses 需要 Responses 上游，Messages 需要 Messages 上游；Chat 可对接 Chat 或内部 Gemini 文本转换。Gemini 原生入口、多模态/工具转换、跨协议转换器不在本次升级内。

CLI 验收包括：启动模型发现、手动指定模型、普通/流式对话、完整工具调用与工具结果回传、失败错误和人民币成本。Anthropic 调用补齐允许透传的 anthropic-beta 与 anthropic-version 请求头；同一凭据同时出现在 Bearer 和 x-api-key 时接受，不同凭据同时出现则拒绝。

外部协议依据（2026-09-14 查阅，实施时核对实测客户端版本）：
- [Claude Code 网关兼容与模型发现](https://code.claude.com/docs/en/llm-gateway-protocol#model-discovery)

## 8. 最小数据变更

| 记录 | 责任 |
| --- | --- |
| UsageGroup | 组织、组类型、名称、状态、预算模式和默认设置 |
| GroupMember | 组与员工关系，同一组与员工唯一 |
| GroupModelAccess | 组明确允许的公共模型，同一组与模型唯一 |
| EmployeeApiKey | 员工、组、密钥摘要、生命周期、展示信息 |
| GroupBudgetPeriod | 当前/历史预算周期的额度、已结算、预占汇总；总额模式用单一长期周期 |
| GroupBudgetEntry | 逐请求持久预占、结算状态及有原因的预算/成本调整记录 |

DeviceGrant 增加组归属；UsageLog 增加 groupId、apiKeyId、credentialType，deviceId 对 API Key 请求允许为空。校验凭据类型与 deviceId/apiKeyId 对应关系，保留旧设备记录兼容。

通过数据库约束及事务校验保证员工、组、Key、预算属于同一组织。预算、日志及历史凭据禁止级联删除。日志保存归属 ID 和必要展示快照，员工转组、对象改名不改写历史归属。

新增字段使用 CNY 命名和 Decimal。旧 costUsd 等字段保留兼容读取，统一说明实际币种来源；后续独立迁移旧命名，不在本次同时大规模改报表接口。

## 9. 兼容迁移与发布

1. 增加数据结构与兼容读取，先不强制所有设备有组；现有调用行为保持，历史日志 groupId 为空并显示“历史未分组”。
2. 管理员创建真实用量组、选模型、分配预算、导入成员并给现有设备授权指定组；提供未分配设备清单及影响预览。
3. 上线员工 API Key 入口，新 Key 从第一天起必须绑定有效组并通过组权限与预算检查。
4. 对已完成迁移的组织启用“设备也必须归组”；未分配设备明确拒绝。启用前检查覆盖率，管理员明确切换，不默认为所有人创建无限额组。
5. 对切换前在途设备请求保留开始时归属和旧结算逻辑；切换后新请求执行新规则。
6. 验证 API Key 和 UCLI 两种路径均正确后再完成全组织切换。

回退必须使用已理解组权限和预算的新版本兼容代码；直接恢复完全忽略组预算的旧网关会绕过控制。发生重大故障可暂时停止新 Key 调用，保留并处理已有预算记录。数据库采取向前兼容迁移，不删除预算或使用数据。

## 10. 实施顺序与验收

1. 用量组、成员、模型允许清单和数据库约束；完成管理端组详情。
2. 员工 API Key 签发/撤销与网关身份统一；完成用户详情及个人接入页。
3. 组预算预占、结算、恢复与调整；补齐流式、取消和重试的成本归属。
4. 使用日志和统计增加组/Key 维度；完成 UCLI 设备归组迁移工具及组织切换。

金额控制完成前，新的 Key 入口只在测试环境启用，不提前开放生产有限预算场景。

验收以可观察结果为准：

- 同一员工分别用 A/B 组 Key 调用，日志及费用只落对应组，模型权限不能跨组借用。
- 外部 OpenAI 兼容工具能列模型并完成普通/流式对话；既有 UCLI 和 Anthropic 路径回归通过。
- 两种目录都按 Key 所属组过滤，Anthropic 目录再按协议过滤；重复认证头相同则接受、冲突则拒绝。
- 同一 Key 完成模型发现、流式和工具调用闭环；不依赖客户端名称或可伪造的项目上下文取得组权限。
- 错误 Key、撤销、到期、停用员工/组、移出组，以及跨组织尝试均被拦截；员工 Key 不能访问管理接口。
- 空模型清单、未授权模型 ID、零预算均明确拒绝；目录与实际调用判断一致。
- 多个并发请求竞争最后额度时不能重复预占；已知成本只结算一次。
- 流中断、上游错误/模糊超时、路由切换、缺 usage、数据库失败与重启均可追踪，不静默归零或丢失预占。
- 月界、时区、价格切换、限额调整、极小成本及超预占结算符合既定规则。
- 员工转组、Key 撤销或组归档后，历史员工姓名、组归属、渠道、模型、价格快照和成本仍可查询。
- 旧数据不自动归入新组，迁移前后公司总成本可对账；无真实支付或销售价格功能。

## 11. 一期边界

一期交付组、成员、Key、模型允许清单、两种组预算模式和统计，不增加组织树、跨组费用分摊、组间自动调拨、充值支付、审批流、组管理员或每 Key 独立预算。后续以实际管理需求决定扩展。

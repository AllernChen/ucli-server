# 0.6.0：平台 API Key 管理与个人中心

状态：2026-09-17 用户确认，已在隔离分支实施；本地验收见 `docs/verification/2026-09-17-personal-center.md`，未部署。已确认调整：移除“我的接入”菜单，不做旧地址自动跳转；API Keys 管理放在个人中心。管理权限沿用既定方案。

## 1. 目标与现状

移除“我的接入”菜单，新增独立“个人中心”，集中承接个人资料、安全设置、API Keys 管理、所属用量组和个人用量。API Keys 管理不再作为侧边栏独立入口。

原规划已获确认并进入实施；本次业务实现不修改版本号或部署环境。

代码依据：当前工作目录位于 `codex/device-grant-link-management`，尚无“我的接入”。已通过 Git 只读检查 `codex/group-access` 的 `b1f5312`（0.4.0）实现：

- `MyAccess.vue`：员工 Key 列表、接入地址、PowerShell 示例。
- `EmployeeKeysPanel.vue`：个人查看/撤销；管理员在用户详情中创建、编辑、启停、撤销、删除。
- `EmployeeKeysController`：已有按员工查询及个人查询，缺少管理员集中查询接口。
- `App.vue`：已有角色导航和修改密码弹窗；普通成员默认进入“我的接入”。
- `AuthService.me`：当前仅返回 ID、显示名称、组织 ID 和角色。新建员工默认无密码，不能直接网页登录。

2026-09-17 已核对发布基线：`v0.5.1` 指向 `6748455`，`origin/main` 的 `13048b0` 仅追加 0.5.1 发布验证文档；该发布记录载明公司服务器已升级至 0.5.1。0.6.0 应从包含此基线的分支开展，不能把当前 0.3.x 工作目录直接作为开发起点。上述 Key 与身份代码在 0.5.1 中保持一致；日志和统计应复用 0.5.1 的共享查询与筛选实现。

## 2. 信息架构与方案选择

采用个人中心内的“API Keys”页签，按身份限定数据和操作；列表、管理动作和接入说明均在该页签内完成。

不新增独立 API Keys 菜单，也不保留“我的接入”菜单。上游渠道密钥仍在渠道管理，避免混淆采购凭据与员工调用凭据。

| 入口 | 职责 | 建议位置 |
| --- | --- | --- |
| 个人中心 `/profile` | 我的资料、安全、API Keys、所属组、个人用量 | 侧边栏底部账号区 |
| API Keys `/profile?tab=api-keys` | 平台签发的员工 API Key、接入说明 | 个人中心内的页签 |
| 渠道管理 | 上游供应商渠道密钥 | 保持现有入口 |
| 授权令牌 | UCLI 设备授权生命周期 | 保持现有管理入口 |

“统一”指入口统一，不代表全员共用一个 Key。每个 Key 仍固定归属一个员工、一个用量组。

旧 `/my-access` 地址不做自动跳转；本次移除菜单及站内入口引用，不额外要求删除旧路由实现。用户详情保留当前员工的 Key 快捷入口，复用同一组件和服务。普通成员登录默认进入个人中心；管理员保留原有合法默认入口，原先落到“我的接入”的改到个人中心。无权限页面的回退入口也指向个人中心。

## 3. 个人中心：API Keys 页签

页签内采用“标题和操作 → 筛选 → 列表 → 详情抽屉”的结构，接入说明作为独立抽屉，不占据主列表空间。

### 列表与查询

- 顶部：页面说明、刷新、接入说明；管理员可见“创建 Key”。
- 搜索：Key 名称、脱敏尾号；管理员另可按员工姓名/邮箱搜索。
- 筛选：员工（管理员）、用量组、状态；支持分页并保留当前筛选条件。
- 列：名称/尾号、所属员工、所属组、状态、创建时间、到期时间、最后使用时间、操作。员工视图省略重复的本人列。
- 状态优先级：已撤销 → 已停用 → 已过期 → 有效。有效仅代表 Key 自身状态，不承诺组预算、模型权限或上游可用。
- 空列表显示接入引导；无可用组时说明需先加入组；加载失败提供重试，不能显示成“暂无 Key”。

### 创建与管理

创建抽屉包含：所属员工、所属组、名称、到期时间。先选择员工，再加载该员工的有效组；服务端再次验证归属。名称用来区分工具或用途，不新增一套用途分类。

沿用既有能力：编辑名称/到期时间、停用、启用、永久撤销、删除。删除明确表述为“撤销并从列表移除”，历史用量和审计仍保留。员工与组归属不可编辑。

完整 Key 仅创建成功时展示一次并支持复制；关闭后不能再次查看。轮换按“创建替代 Key → 客户端更新验证 → 撤销旧 Key”执行，不在创建新 Key 时自动撤销旧值。

详情抽屉展示基本信息、归属、生命周期和创建人，并提供“查看该 Key 使用日志”。本期复用日志和统计页面，不在列表逐行计算费用或新增图表。

### 接入说明

展示 OpenAI 兼容与 Anthropic 接入地址、环境变量配置示例、模型发现示例和常见失败解释。示例只引用环境变量或占位符，不嵌入真实密钥。协议能力以已配置模型为准。

### 权限

| 能力 | 平台/组织管理员 | 普通员工 |
| --- | --- | --- |
| 查询 Key | 当前授权组织范围内全部，可筛选员工 | 本人、当前组织范围 |
| 创建、编辑、启停、删除 | 允许 | 不开放 |
| 永久撤销 | 授权范围内 | 仅本人 |
| 使用日志 | 既有授权范围 | 仅本人 |
| 查看完整 Key | 创建成功时一次 | 不提供找回入口 |

默认延续当前组织隔离。平台管理员的菜单权限不自动变成跨组织数据查询权限；跨组织汇总需要另行明确授权模型。所有校验在后端执行，不能仅靠隐藏按钮。

## 4. 个人中心

顶部显示姓名、邮箱、当前组织和角色；下方使用五个页签。

| 页签 | 0.6.0 内容 | 可执行操作 |
| --- | --- | --- |
| 基本资料 | 显示名称、登录邮箱、组织、角色、账号状态 | 修改本人显示名称；其余只读 |
| 账号安全 | 修改密码、密码修改后的会话提示 | 校验旧密码后修改，成功后重新登录；退出当前登录 |
| API Keys | Key 列表、管理操作、接入说明，详见第 3 节 | 员工查看/撤销本人 Key；管理员可切换授权范围内管理视图 |
| 我的用量组 | 组名称、类型、状态、本人归属；可用模型入口 | 查看本人可见信息，不能自行加组、改权限或改预算 |
| 我的用量 | 选定周期的本人请求数、Token、人民币成本，按组汇总 | 跳转已限定本人范围的日志和统计 |

选择“API Keys”页签即可管理 Key，无需跳出个人中心。默认显示本人 Key；管理员可在页签内显式切换“我的 Key / 组织 Key”，后者仅覆盖当前授权组织范围。

组预算属于共享额度，不能显示为个人余额；本期个人中心展示个人已用成本，不默认暴露其他组员明细或整个组的财务信息。费用沿用现有口径，估算标识不能丢失。

安全页迁入现有修改密码能力，不重复保留全局弹窗。当前密码修改会递增 `tokenVersion`；实施时需验证网页与设备 Token 的实际失效/刷新行为并准确提示，不能擅自承诺仅影响当前浏览器。密码修改不等于撤销员工 API Key。

### 网页登录前提

当前无密码员工不能登录，个人中心本身不会解决账号开通问题。本草案默认面向已具备网页登录能力的账号；无密码员工仍可使用管理员签发的 Key。

如果 0.6.0 要求所有员工自助访问个人中心，必须同时纳入“管理员发起账号激活、一次性限时设置密码”的流程，并另行细化交付渠道与验证规则。不能用员工 API Key 兑换网页登录身份，也不能通过公开邮箱直接设置密码。

## 5. 实现边界与顺序

1. 核对发布基线及登录覆盖要求，确定个人中心路由、API Keys 页签和角色导航。
2. 复用 `EmployeeKeysService` 和 `EmployeeKeysPanel`，新增管理员集中查询、服务端搜索筛选和归属展示；保留原有按用户接口与生命周期操作。
3. 新增个人中心。扩展当前身份查询的安全展示字段，新增仅允许修改本人显示名称的接口；复用修改密码接口。
4. 复用个人组查询、使用日志和统计，按需增加最小摘要查询。个人接口从登录身份获取 accountId，不接受客户端扩大数据范围。
5. 将接入说明迁入 API Keys 页签，移除“我的接入”菜单及站内引用，更新默认登录落点和无权限回退；不新增旧地址重定向。

本期不增加独立 Key 数据模型、不重新签发现有 Key、不改变调用协议和组预算结算。资料更新使用字段白名单、长度校验并记录必要审计；身份响应不返回密码摘要、密钥摘要或其他凭据。

## 6. 验收标准

- 管理员可直接集中查找员工 Key，无需逐个进入用户详情；创建、编辑、启停、撤销流程闭环。
- 员工只能查询和撤销自己的 Key；伪造员工、组织、组或 Key ID 不能越权，统计总数也不能泄露其他人的数据。
- 新建 Key 的员工和组校验正确，明文只展示一次；撤销或删除后不能恢复，历史调用仍可追溯。
- 修改本人名称后账号区和个人中心同步更新；邮箱、角色、组织等字段不能通过修改请求越权变更。
- 修改密码的原密码校验、生效范围及重新登录行为符合既有认证机制，设备刷新路径有回归覆盖。
- 个人用量与相同筛选条件的使用日志一致；共享组预算不被展示为个人余额。
- 侧边栏没有“我的接入”或独立 API Keys 菜单，API Keys 管理完整位于个人中心；旧 `/my-access` 地址不自动跳转。
- 角色导航、API Keys 页签直达链接、登录默认落点和无权限回退可用，不再将用户引向“我的接入”；加载、空数据、失败和提交中状态完整。
- 规划仅面向已开通网页登录的账号时明确说明限制；若要求全员可用，账号激活闭环必须纳入验收。

## 7. 暂不纳入

员工自助签发 Key、每 Key 独立预算、批量密钥操作、跨组织 Key 总览、头像上传、邮箱自助更换、手机号、消息中心、MFA、设备自助撤销、登录会话列表和完整密码找回系统。本期不新增基础设施或依赖。

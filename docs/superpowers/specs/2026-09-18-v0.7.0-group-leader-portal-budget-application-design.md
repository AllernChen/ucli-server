# 0.7.0：组负责人门户、员工登录与预算申请登记

状态：设计已按需求讨论确认（2026-09-18），进入实施规划；尚未实施。基于 0.6.0 主线（`origin/main`）增量开发。

## 1. 目标与现状

0.6.0 已交付用量组、员工 API Key、组预算与个人中心，但有三处与公司实际管理流程的缺口：

| 缺口 | 现状 | 0.7.0 目标 |
| --- | --- | --- |
| 普通员工无密码，登不进个人中心 | 后台新建用户 `passwordHash: null`，密码登录直接 401；设计上"查询由管理员代办" | 管理员为员工设置初始密码，员工可登录个人工作台查看本人 Key、所属组与用量 |
| 组的预算与消耗只有管理员可见 | 用量组管理接口全部 `PLATFORM_ADMIN/ORG_ADMIN` | 组负责人（只读）登录后可查看所负责组的预算执行、调整台账、申请记录与成员用量 |
| 预算申请记录不留存 | 平台只记录批复后的额度调整（LIMIT_ADJUSTMENT），申请过程在线下 | 平台登记每次预算申请；批复后与额度调整流水自动关联，形成"申请 → 批复 → 调整"完整台账 |

不改变 0.6.0 的既有边界：无组织树、无组嵌套、无跨组费用分摊、无审批流引擎、无组管理员写权限。负责人能力是**只读 + 提交申请登记**。

## 2. 员工初始密码与登录

### 方案选择

| 方案 | 结论 | 原因 |
| --- | --- | --- |
| 管理员设置初始密码（创建时可选填 / 事后补设 / 重置） | 采用 | 平台无邮件/短信通道，不引入新依赖；公司内部规模（几十人）管理员经企业微信转达可接受 |
| 首次登录激活链接（类设备授权链接） | 暂不采用 | 需要安全传输通道把链接交给员工，本质与转达初始密码相同，多一套链接生命周期要维护 |
| 自助注册/找回 | 不做 | 私有部署、账号预创建模式；忘记密码由管理员重置 |

### 规则

- `CreateManagedUserDto` 增加可选 `initialPassword`（≥8 位，沿用现有校验）；不填则保持现状（无密码，仅用 Key）。
- 新增管理操作 `POST /api/v1/admin/users/:id/reset-password`：设置新密码哈希、`tokenVersion + 1`（使该账号现有网页 JWT 全部失效）、写审计日志。对已有无密码账号即"补设密码"，对已有密码账号即"重置密码"。
- 登录、改密流程不变；员工首次登录后在个人中心「账号安全」自行改密（0.6.0 已有能力）。
- 初始密码在响应中回显一次（管理员创建/重置时），与员工 API Key"仅创建时展示"的精神一致；不落日志。
- 边界：不做密码找回、不做密码过期策略、不强制所有账号必须有密码（纯 Key 使用者可继续无密码）。

## 3. 组负责人角色

### 数据模型

`GroupMember` 增加 `role GroupMemberRole @default(MEMBER)`（`LEADER | MEMBER`），配 Prisma 迁移；存量数据自动落 `MEMBER`。一人可以是多个组的负责人；一个组允许多名负责人（对应现实中的组长/项目管理）。

组长归属随成员关系走：移出组（`removedAt`）即失去该组负责人身份与门户可见性，历史用量归属不变。

### 权限模型

- 管理操作（设置/取消负责人）：仅 `PLATFORM_ADMIN/ORG_ADMIN`，在组详情成员列表中操作，写审计日志。
- 负责人能力为**只读 + 预算申请登记提交**：
  - 查看所负责组的预算摘要（额度、已结算、预占、可用、进度、告警状态）；
  - 查看预算调整流水与申请记录；
  - 查看组内成员用量（按成员、按模型聚合及明细分页，仅限本组）；
  - 提交预算申请登记（见 §4）。
- 负责人**不能**：改组配置/预算额度、增删成员、签发或撤销 Key、查看其他组、查看平台级统计。
- 授权校验一律服务端完成：`groupId ∈ 请求者担任 LEADER 的组集合`；前端按接口返回控制展示。
- 网页 JWT 可访问负责人接口；设备会话与员工 API Key 沿用 0.6.0 规则——拒绝（与个人中心身份接口一致，`Cache-Control: no-store`）。

## 4. 预算申请登记

### 数据模型

新增 `GroupBudgetApplication`（配迁移）：

| 字段 | 说明 |
| --- | --- |
| organizationId / groupId | 归属（同组约束） |
| applicantAccountId | 申请人（负责人或代登记的管理员） |
| requestedCny / reason | 申请金额与事由 |
| status | `REGISTERED → LINKED \| REJECTED` |
| approvedCny / decidedById / decidedAt | 批复信息 |
| linkedEntryId | 关联的 `GroupBudgetEntry`（LIMIT_ADJUSTMENT），批复执行后回填 |
| createdAt | 申请时间 |

`GroupBudgetEntry` 表不改——关联放在申请侧，避免动 0.6.0 已上线的记账结构。

### 流程

1. **登记**：负责人在门户提交（金额、事由），或管理员代登记；状态 `REGISTERED`。申请不是资金操作，不占额度、不校验预算余额。
2. **批复**：线下审批完成后，管理员执行额度调整时携带 `applicationId`（`BudgetAdjustmentDto` 增加可选字段）；`adjust` 原子完成"额度调整 + 申请置 `LINKED` + 回填 `linkedEntryId`"。驳回则单独接口置 `REJECTED`（记批复人、时间，可选批复说明）。
3. **台账**：组详情与负责人门户展示申请列表（状态、申请/批复金额、关联调整流水），调整流水侧也可反查来源申请。

兼容：不带 `applicationId` 的既有调整流程完全不变。

## 5. 页面与接口

| 页面/入口 | 内容 |
| --- | --- |
| 用户详情（管理端） | 设置/重置密码操作（回显一次）；无密码账号标注"未设置密码，仅 Key 访问" |
| 用量组详情（管理端） | 成员列表增加"负责人"标记与设置/取消操作；「预算与申请记录」页签（申请列表 + 既有调整流水合并时间轴） |
| 个人中心「我负责的组」页签 | 担任负责人的组卡片：额度/已用/预占/可用/进度/告警；进入单组只读视图（预算摘要、申请记录、成员用量聚合与明细）；「提交预算申请」表单与本组申请状态跟踪 |
| `GET /api/v1/me/led-groups` | 我负责的组列表 + 预算执行总览 |
| `GET /api/v1/me/led-groups/:id/budget` `/budget-applications` `/usage` | 单组预算摘要 / 申请记录 / 用量（聚合+明细分页） |
| `POST /api/v1/me/led-groups/:id/budget-applications` | 负责人提交申请登记 |
| `POST /api/v1/admin/users/:id/reset-password` | 管理员设置/重置初始密码 |
| `POST /api/v1/admin/usage-groups/:id/members/:accountId/leader`（及 DELETE） | 设置/取消负责人 |
| `POST /api/v1/admin/usage-groups/:id/budget-applications/:appId/decision` | 批复登记（驳回；批准走带 applicationId 的 budget-adjustments） |

## 6. 验收标准

- 无密码账号被设置初始密码后可登录个人中心、看到五个既有页签并能改密；重置密码后其旧网页 JWT 立即失效；设备会话与员工 API Key 行为不回归。
- 创建用户不填初始密码时行为与 0.6.0 完全一致（无密码、仅 Key）。
- 负责人仅能看到所负责组的预算、申请与成员用量；访问未担任负责人的组返回 403；负责人调用任何组写接口返回 403。
- 成员被移出组后，其负责人身份即时失效（门户与接口均不可见），历史数据归属不变。
- 申请登记 → 带申请 ID 的额度调整 → 申请状态 `LINKED` 且流水可互查；驳回路径状态正确；不带申请 ID 的调整不受影响。
- 负责人接口拒绝设备会话与员工 API Key；响应带 `Cache-Control: no-store`。
- 存量 `GroupMember` 迁移后全部为 `MEMBER`，既有组、预算、Key 行为无回归；`npm run verify` 全绿。

## 7. 暂不纳入

密码找回/邮箱通道、密码过期策略、多级审批流、组内职能角色（市场/项目管理/技术管理）、组层级或跨组汇总视图、跨组成本划转、负责人代签 Key。

# 0.6.0 个人中心与 API Keys Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 本计划适合在同一任务内顺序执行，无需并行修改共享文件。

**Goal:** 移除“我的接入”菜单，将 API Keys 管理与个人资料、安全、所属组、个人用量统一放入个人中心。

**Architecture:** 基于 0.5.1 复用员工 Key 的数据模型、生命周期接口、组权限和统计查询。在现有服务中增加集中查询与本人资料能力；新增个人中心视图，将已有 Key 面板和密码操作迁入其中。权限由服务端保证，前端按角色控制展示。

**Tech Stack:** Vue 3、Vue Router、NestJS、Prisma/PostgreSQL、Vitest、Vue Test Utils；不新增依赖。

**Spec:** `docs/superpowers/specs/2026-09-16-v0.6.0-key-management-personal-center-design.md`

## 全局约束

- 移除“我的接入”菜单，不新增独立 API Keys 菜单，不设置 `/my-access` 自动跳转。
- 个人中心五个页签：基本资料、账号安全、API Keys、我的用量组、我的用量。
- Key 固定归属员工和组；普通员工仅查看、撤销本人 Key，管理员管理当前授权组织。
- 完整 Key 仅创建时展示一次；服务端、浏览器存储、URL、日志不得新增明文持久化。
- 个人中心的本人查询对管理员也必须限制为本人；组织 Key 视图必须显式切换。
- 不修改数据库结构、组预算结算、网关调用协议；不重新签发已有 Key。
- 覆盖已具备网页登录能力的账号，不新增账号激活、首次设密或密码找回流程。
- 本计划不包含部署、发布标签或生产操作。版本号在后续发布准备时处理。

## Task 4：本人用量组、模型与用量查询

**Create:** `apps/api/src/profile.controller.ts`、`test/auth/profile-reads.test.ts`。**Modify:** `app.module.ts`。复用 `PrismaService`、`ModelCatalogService`、`AnalyticsService`，不复制计费 SQL。

**接口：** 控制器基址 `/api/v1/me/profile`，全部仅允许网页登录并设置 no-store：

- `GET usage-groups`：返回当前组织、本人未移出成员关系的组，字段 `{ id, name, type, enabled, archivedAt, joinedAt }`；包含停用/归档状态，不含预算及他人成员信息。保持原 `/me/usage-groups` 的有效组选择语义不变。
- `GET usage-groups/:id/models`：UUID 校验，调用 `ModelCatalogService.list`，身份中的 organizationId/accountId/role 来源于登录，groupId 来源于已校验路径。由既有服务验证有效成员和组权限，禁止读取未加入的组；返回既有模型目录结构。
- `GET usage`：接收已有 `AnalyticsQueryDto`，返回 `{ overview, groups }`；overview 沿用 `AnalyticsService.overview` 返回类型，groups 沿用 `breakdown` 分页返回类型，维度固定 group。显式覆盖查询的 organizationId/accountId，其他筛选沿用已有校验。

# 0.7.0 组负责人门户、员工登录与预算申请登记 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 本计划适合在同一任务内顺序执行，Task 2/3 相互独立可并行，其余任务有依赖请按序执行。

**Goal:** 让普通员工能登录个人中心（管理员设初始密码），组负责人能在门户查看所负责组的预算执行、申请记录与成员用量，并把线下预算申请以登记记录留存在平台、与额度调整流水关联。

**Architecture:** 基于 0.6.0 现有 AuthGuard/个人中心/用量组/组预算体系增量扩展：`GroupMember` 加角色列、新增 `GroupBudgetApplication` 表、新增 `me/led-groups` 只读接口族与个人中心页签；不改动网关、预算预占结算、既有记账结构。

**Tech Stack:** NestJS、Prisma/PostgreSQL（迁移）、Vue 3 `<script setup>`、Vitest；不新增依赖。

**Spec:** `docs/superpowers/specs/2026-09-18-v0.7.0-group-leader-portal-budget-application-design.md`

## 全局约束

- 基线为 `origin/main`（0.6.0 已发布）。当前工作目录在旧分支 `codex/device-grant-link-management`，实施必须使用包含 0.6.0 的隔离工作区，不得在本目录直接切分支或覆盖未提交文件。
- Prisma schema 变更必须随附 `prisma/migrations/` 迁移文件；存量 `GroupMember.role` 默认 `MEMBER`。
- 负责人接口服务端校验 `groupId ∈ 请求者的 LEADER 集合`；全部响应 `Cache-Control: no-store`；拒绝设备会话与员工 API Key（沿用 `profile` 控制器既有规则）。
- 初始密码/重置密码回显仅一次，不写应用日志与审计 metadata；重置必须 `tokenVersion + 1`。
- 隐私边界不放松：负责人可见的用量仅限本组；不新增请求正文日志。
- 中文提交信息；每个 Task 结束跑 `npm run typecheck && npx vitest run test/<相关目录>`，最终 `npm run verify` 全绿。

## Task 1：实施基线与数据模型

- [ ] 从 `origin/main` 创建隔离工作区并确认基线：`git log -1` 指向 0.6.0 之后提交，`npm run verify` 通过。
- [ ] `prisma/schema.prisma`：新增 `enum GroupMemberRole { LEADER  MEMBER }`；`GroupMember` 增加 `role GroupMemberRole @default(MEMBER)`。
- [ ] 新增 `GroupBudgetApplication` 模型：组织/组/申请人/申请金额/事由/状态（`REGISTERED/LINKED/REJECTED`）/批复金额/批复人/批复时间/`linkedEntryId`（关联 `GroupBudgetEntry`，`Restrict`）；组织内同组约束沿用现有复合外键写法。
- [ ] 生成迁移文件并 `npm run db:generate`；迁移在本地数据库执行验证可前滚。

## Task 2：员工初始密码与重置

- [ ] `CreateManagedUserDto` 增加可选 `initialPassword`（8–128 位校验）；`UsersService.create` 传入时哈希存储，响应回显一次初始密码字段；不传时行为与 0.6.0 一致。
- [ ] 新增 `POST /api/v1/admin/users/:id/reset-password`（`Roles` 与既有用户管理一致）：校验目标成员属于操作者组织、设置新哈希、`tokenVersion + 1`、审计日志（metadata 不含密码）、响应回显一次。
- [ ] 测试（`test/users`）：创建带/不带初始密码；重置后旧 JWT 失效、新密码可登录；无权限组织返回 404/403；密码长度校验。
- [ ] 前端 `UserDetail.vue`：无密码账号显示"未设置密码"标注与「设置/重置密码」操作，回显弹窗仅一次。

- [ ] 前端 `UsageGroupDetail.vue`：成员列表负责人标记与设置/取消操作。

## Task 4：负责人只读接口

- [ ] 新增 `LedGroupsController`（`api/v1/me/led-groups`，AuthGuard + 拒绝设备会话/API Key 会话 + `no-store`）：
  - `GET /`：担任 LEADER 的组列表 + 预算执行概览（复用 `GroupBudgetService` 摘要与告警状态计算，仅读取）。
  - `GET /:id/budget`：单组预算摘要；`:id` 不在 LEADER 集合返回 403。
  - `GET /:id/usage`：组内用量——按成员、按模型聚合并支持明细分页（复用 `usage-query.ts` 过滤构造，限定 `groupId`）。
- [ ] `GET /:id/budget-applications`（Task 5 表就绪后补数据）先挂路由。
- [ ] 测试（`test/usage-groups` 或新 `test/led-groups`）：负责人可读本组、读他组 403、普通成员空列表、设备会话 401/403、用量仅含本组数据、`no-store` 头存在。

## Task 5：负责人提交预算申请 + 批复关联

- [ ] `POST /api/v1/me/led-groups/:id/budget-applications`：负责人提交（金额 CNY、事由必填），状态 `REGISTERED`；同接口族鉴权规则一致。
- [ ] `BudgetAdjustmentDto` 增加可选 `applicationId`；`GroupBudgetService.adjust` 校验申请属于本组且 `REGISTERED`，同一事务内置 `LINKED`、回填 `linkedEntryId`、approvedCny/decidedBy/decidedAt。
- [ ] `POST /api/v1/admin/usage-groups/:id/budget-applications/:appId/decision`：驳回（置 `REJECTED`，记批复人/时间/说明）；管理员也可用 `me` 外的管理端代登记接口创建申请（复用同一服务方法）。
- [ ] 测试：申请创建/列表；带 applicationId 调整成功后状态与关联正确；重复批复/非本组申请/已 LINKED 再调整被拒；驳回路径；不带 applicationId 的既有调整回归通过。
- [ ] 前端：`UsageGroupDetail.vue`「预算与申请记录」页签（申请与 LIMIT_ADJUSTMENT 合并时间轴，申请行展示状态与关联流水）。

- 三个需求全部落到可验收条目：初始密码（Task 2）、负责人只读门户（Task 3/4/6）、申请登记与关联（Task 5）。

- 未触碰网关转发、预算预占/结算主路径与隐私边界；既有接口无破坏性变更（新增字段均为可选）。

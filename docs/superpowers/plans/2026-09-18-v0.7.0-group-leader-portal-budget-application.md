# 0.7.0 组负责人门户、员工登录与预算申请登记 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 本计划适合在同一任务内顺序执行，Task 2/3 相互独立可并行，其余任务有依赖请按序执行。

**Goal:** 让普通员工能登录个人中心（管理员设初始密码），组负责人能在门户查看所负责组的预算执行、申请记录与成员用量，并把线下预算申请以登记记录留存在平台、与额度调整流水关联。

**Architecture:** 基于 0.6.0 现有 AuthGuard/个人中心/用量组/组预算体系增量扩展：`GroupMember` 加角色列、新增 `GroupBudgetApplication` 表、新增 `me/led-groups` 只读接口族与个人中心页签；不改动网关、预算预占结算、既有记账结构。

**Tech Stack:** NestJS、Prisma/PostgreSQL（迁移）、Vue 3 `<script setup>`、Vitest；不新增依赖。

**Spec:** `docs/superpowers/specs/2026-09-18-v0.7.0-group-leader-portal-budget-application-design.md`

## 全局约束

- 基线为 `origin/main`（0.6.0 已发布）。当前工作目录在旧分支 `codex/device-grant-link-management`，实施必须使用包含 0.6.0 的隔离工作区，不得在本目录直接切分支或覆盖未提交文件。
- Prisma schema 变更必须随附 `prisma/migrations/` 迁移文件；存量 `GroupMember.role` 默认 `MEMBER`。
- 负责人接口服务端校验 `groupId ∈ 请求者的 LEADER 集合`；全部响应 `Cache-Control: no-store`；拒绝设备会话与员工 API Key（沿用 `profile` 控制器既有规则）。
- 初始密码/重置密码回显仅一次，不写应用日志与审计 metadata；重置必须 `tokenVersion + 1`。
- 隐私边界不放松：负责人可见的用量仅限本组；不新增请求正文日志。
- 中文提交信息；每个 Task 结束跑 `npm run typecheck && npx vitest run test/<相关目录>`，最终 `npm run verify` 全绿。
